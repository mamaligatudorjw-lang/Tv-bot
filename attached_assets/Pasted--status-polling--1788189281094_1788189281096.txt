# Расширить /status диагностикой polling и позиций (номер уточнить у дева — новый отдельный тикет)

*(Не #180 и не #6 — отдельная задача. #6 "Видеть в /status, сколько слотов LONG/SHORT занято" имеет узкий scope — квоты `_active_monitors` — и её трогать не нужно; у этого тикета другие критерии готовности, формат данных и риски безопасности. Рекомендуется сделать зависимой от #6, чтобы оба изменения не редактировали `handle_status_command` параллельно.)*

## What & Why

Status endpoint из #167 сейчас отдаёт `post_fix_leak`-метрики (count, alert flag, relay-health отдельно от gate-integrity). Нужно добавить туда же операционные факты, которые иначе приходится каждый раз запрашивать у дева вручную (как в вопросе про 2 открытые позиции на Bybit) — чтобы можно было проверять здоровье системы одним HTTP-запросом.

## Confirmed

- Только добавление полей в существующий read-only endpoint — не новый endpoint, не изменение auth-модели без явного решения (см. ниже).
- Никаких изменений в торговой логике, gating, whitelist — только отчётность.

## Поля для добавления

1. `last_signal_at` — timestamp последнего сгенерированного сигнала, по любой стратегии.
2. `last_successful_poll_at` — timestamp последнего успешного опроса Bybit demo API (polling, не websocket — см. #160), плюс `polling_stale` (bool) с явным порогом (например, > 2х обычного интервала опроса).
3. `active_whitelist` — список текущих 3 активных слотов (strategy + confirmation level), включая явный статус решения по `overheated_early` (#167).
4. `open_positions` — список открытых Bybit demo позиций: strategy, symbol, `opened_at` (без чувствительных деталей вроде API-ключей, разумеется).

## Нужно решить перед реализацией

**Аутентификация.** Endpoint будет опрашиваться извне (в т.ч. мной через WebFetch) — если он сейчас полностью открыт без токена, `open_positions` и `active_whitelist` — это операционные данные, которые не стоит держать публично доступными без всякой защиты. Уточнить у дева: endpoint уже за каким-то auth (API key/токен), или нет — если нет, добавить простой токен в query/header, не завязанный на секреты биржи.

## Done looks like

- Расширенный endpoint отдаёт все 4 поля.
- Явно описано, что считается "stale" для polling.
- Тесты: корректный формат ответа, `polling_stale` срабатывает при устаревшем timestamp.
- Подтверждено, есть ли auth, и если нет — добавлен минимальный токен.

## Out of scope

- Изменение самой торговой/gating логики.
- Новый отдельный сервис/endpoint — расширяется существующий.
