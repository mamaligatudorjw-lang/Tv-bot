# #164 — Прокси-релей для обхода блокировки Bybit по региону (США → Replit)

*(Follow-up к #163: код и тесты готовы, live-подтверждение заблокировано CloudFront 403 из-за US-региона исходящего IP Replit.)*

## What & Why

Bybit блокирует запросы (и публичные, и подписанные) с IP из США — подтверждено на всех трёх эндпоинтах (`api-demo.bybit.com`, `api.bybit.com`, `www.bybit.com`), Replit выходит именно через US (Google Cloud, South Carolina). Аккаунт и пользователь — из Молдовы, которая не входит в список ограничений Bybit; проблема чисто в маршруте исходящего трафика, не в аккаунте.

Решение: **прокси-релей** в разрешённой стране, через который идут только запросы к Bybit — не полный переезд хостинга и не смена биржи.

## Confirmed

- Регион релея — страна, где реально зарегистрирован/верифицирован аккаунт (Молдова или любая другая страна ЕС не из списка ограничений Bybit) — не произвольная страна ради обхода, а соответствующая фактической юрисдикции пользователя.
- Через прокси идут **только** запросы к `*.bybit.com` — остальной трафик бота (Telegram API, SQLite, прочие внешние вызовы) не трогаем, чтобы не расширять зону изменений сверх необходимого.

## Confirmed — требования к безопасности relay

- Relay **не является открытым универсальным прокси** — принимает запросы только от бота (например, по клиентскому сертификату/токену/IP-привязке, не от произвольного источника).
- **Allowlist доменов** — разрешены только `*.bybit.com`, всё остальное отклоняется на уровне самого relay, а не только на уровне клиента бота.
- Только **HTTPS**, без даунгрейда до plain HTTP.
- **Заголовки с API-ключами не логируются** — ни в access-логах, ни в error-логах relay.

## Done looks like

- Поднят небольшой relay (VPS/прокси-сервис) в разрешённом регионе, принимающий и перенаправляющий HTTPS-запросы к Bybit, с ограничениями из раздела выше.
- HTTP-клиент бота для Bybit-запросов настроен на использование этого прокси (конфигурируемо — адрес/порт/креды через Replit Secrets, не хардкод).
- Проверка по нарастающей:
  1. Публичный `GET /v5/market/time` через прокси — ожидается 200 вместо текущего 403.
  2. Подписанный private-запрос (например, баланс демо-счёта) через прокси — тоже 200.
  3. Один реальный тестовый ордер на **$50** (из уже одобренного в #163 диапазона) с TP/SL — с проверкой idempotency и последующего polling статуса.
- Если прокси недоступен — явная, видимая ошибка/алерт, а не тихий сбой (не пытаться слать ордера в никуда, как #163 уже корректно делает при 403).
- Задокументировано как эксплуатационная зависимость: релей может отвалиться (хостинг, истечение прокси-креденшелов) — нужен базовый мониторинг доступности, не только на момент первого теста.

## Out of scope

- Полный переезд хостинга бота с Replit.
- Смена биржи для этой функции.
- Расширение #163 за пределы уже одобренных трёх стратегий / фиксированного $50.
