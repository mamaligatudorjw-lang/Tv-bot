## 1. Двойной учёт закрытий — прямое следствие, подтверждённое проектной памятью

В `.agents/memory/bybit-aggregate-close-allocation.md` уже описано: одна закрывающая запись Bybit может покрывать несколько entry-строк, и её PnL нужно **разделять между совпадающими строками ledger'а по `executed_qty`**. Логика верна — но она делит закрытие **внутри одного ledger'а**, исходя из того, что все вкладчики позиции там присутствуют.

При двух рантаймах это условие нарушено: в ledger'е workspace лежит 3 346 единиц ESPORTSUSDT, на бирже — 13 329. Когда агрегат закроется, **каждый рантайм разделит один и тот же обмен-close внутри своего подмножества** и запишет себе результат. То есть реализованный PnL будет учтён дважды — в обеих базах.

Практическое следствие: **вся статистика результативности, посчитанная по любой из двух баз, завышена** для каждой позиции с кратностью > 1×. Это 8 из 12. Под вопросом оказываются как раз недавние аналитические работы — trailing shadow, TP-vs-SL grid, trend regime.

## 2. Кратности 3.11× и 3.98× — вероятно, не баг duplicate-guard, а незаучтённое взаимодействие

В `_demo_open_position` (комментарий на 2231-2232) независимость по стратегиям заявлена намеренно: открытый `ema_cross` LONG не блокирует `overheated_24h` LONG по той же монете. На Bybit в one-way режиме такие заявки **сливаются в одну позицию**. То есть N стратегий по одному символу = N × $50 в одной нетто-позиции — по проекту, а не по ошибке.

Дефект тут не в duplicate-guard, а в том, что **логика лимита экспозиции не знает об этом слиянии**. Формулировать стоит именно так, иначе будет чиниться не то.

## 3. Три сироты (~$145) — единственные позиции вообще без автоматического выхода

`DOSUSDT`, `ENSOUSDT`, `XANUSDT` не сопровождаются ни одним ledger'ом: у них нет ни SL/TP-мониторинга, ни опроса закрытия, ни в одном из рантаймов. Остановка workspace на них не влияет — они уже сейчас без управления. Но это значит, что решение по ним нужно принимать **отдельно и не откладывая**: либо ручное закрытие, либо recovery-запись в ledger published, чтобы их подхватило штатное сопровождение.

Разница ledger-времён по `ESPORTSUSDT` (311 с) и `MUSDT` (770 с) — это, судя по всему, не одна позиция, увиденная дважды, а **две разные заявки**, слитые биржей. На вывод по критерию остановки не влияет, но подтверждает механизм.
